# 12 — TF2 (coordinate frames)

**Goal:** publish where things are relative to each other, and ask TF2 to do
the maths for you.

**Code:** [`static_tf_broadcaster.py`](../src/ros2_basics_py/ros2_basics_py/static_tf_broadcaster.py),
[`tf_broadcaster.py`](../src/ros2_basics_py/ros2_basics_py/tf_broadcaster.py),
[`tf_listener.py`](../src/ros2_basics_py/ros2_basics_py/tf_listener.py),
[`tf_demo.launch.py`](../src/ros2_basics_py/launch/tf_demo.launch.py)

## The problem TF2 solves

Your lidar says *"obstacle 2 m ahead"*. Ahead **of the lidar**. The lidar is
bolted 20 cm in front of the robot's centre, and the robot is 3 m from where
it started, rotated 30°.

So where is the obstacle on the map?

You could write that trigonometry by hand for every sensor pair. Or you can
publish each relationship once and let TF2 compose them:

```
        map
         │
       odom
         │
    base_link
      ├── laser
      └── camera
```

Each arrow is a **transform**: a translation plus a rotation from parent to
child. Ask TF2 for `map → laser` and it multiplies the chain for you, at the
timestamp you ask about.

Two rules define the tree:

1. Every frame has **exactly one parent**. Two nodes publishing the same child
   frame is the classic `TF_REPEATED_DATA` warning, and the tree becomes
   nonsense.
2. Transforms are published on `/tf` (changing) or `/tf_static` (fixed).

## Static transforms: things bolted together

A static transform never changes: the laser is where it is on the chassis.
Publish it **once**.

[`static_tf_broadcaster.py`](../src/ros2_basics_py/ros2_basics_py/static_tf_broadcaster.py):

```python
from geometry_msgs.msg import TransformStamped
import rclpy
from rclpy.node import Node
from tf2_ros import StaticTransformBroadcaster


class StaticTfBroadcaster(Node):
    """Publishes a fixed base_link -> laser transform."""

    def __init__(self):
        super().__init__('static_tf_broadcaster')

        self.declare_parameter('parent_frame', 'base_link')
        self.declare_parameter('child_frame', 'laser')
        self.declare_parameter('translation', [0.2, 0.0, 0.15])

        self._broadcaster = StaticTransformBroadcaster(self)
        self.publish_transform()

    def publish_transform(self):
        parent = self.get_parameter('parent_frame').value
        child = self.get_parameter('child_frame').value
        xyz = self.get_parameter('translation').value

        transform = TransformStamped()
        transform.header.stamp = self.get_clock().now().to_msg()
        transform.header.frame_id = parent
        transform.child_frame_id = child

        transform.transform.translation.x = float(xyz[0])
        transform.transform.translation.y = float(xyz[1])
        transform.transform.translation.z = float(xyz[2])

        # Identity rotation as a quaternion (x, y, z, w).
        transform.transform.rotation.x = 0.0
        transform.transform.rotation.y = 0.0
        transform.transform.rotation.z = 0.0
        transform.transform.rotation.w = 1.0

        self._broadcaster.sendTransform(transform)
        self.get_logger().info(
            'published static transform %s -> %s' % (parent, child))
```

Key points:

- **`StaticTransformBroadcaster`**, not `TransformBroadcaster`. It publishes on
  `/tf_static` with `TRANSIENT_LOCAL` durability ([lesson 10](10-qos.md)), so
  nodes that start *later* still receive it. That is why publishing once is
  enough.
- **`header.frame_id` is the parent, `child_frame_id` is the child.** Getting
  these backwards is the most common TF bug, and it produces plausible-looking
  numbers with the wrong sign.
- **The quaternion `(0, 0, 0, 1)` means "no rotation".** An all-zero
  quaternion is invalid and TF2 will reject it. `w = 1.0` is not optional.
- `float(xyz[0])` — the message fields are `float64`; a parameter list of
  integers would raise a type assertion.

There is a ready-made node for this if you do not need your own:

```bash
ros2 run tf2_ros static_transform_publisher \
    --x 0.2 --y 0 --z 0.15 --frame-id base_link --child-frame-id laser
```

## Dynamic transforms: things that move

[`tf_broadcaster.py`](../src/ros2_basics_py/ros2_basics_py/tf_broadcaster.py)
pretends the robot is driving in a circle and publishes `odom → base_link` at
20 Hz:

```python
def quaternion_from_yaw(yaw):
    """Convert a rotation about Z (in radians) into a quaternion tuple."""
    return (0.0, 0.0, math.sin(yaw / 2.0), math.cos(yaw / 2.0))


class TfBroadcaster(Node):

    def __init__(self):
        super().__init__('tf_broadcaster')
        ...
        self._broadcaster = TransformBroadcaster(self)
        self._timer = self.create_timer(0.05, self.publish_transform)

    def publish_transform(self):
        self._angle += self._angular_speed * 0.05

        transform = TransformStamped()
        transform.header.stamp = self.get_clock().now().to_msg()
        transform.header.frame_id = 'odom'
        transform.child_frame_id = 'base_link'

        transform.transform.translation.x = self._radius * math.cos(self._angle)
        transform.transform.translation.y = self._radius * math.sin(self._angle)
        transform.transform.translation.z = 0.0

        # Face along the direction of travel.
        qx, qy, qz, qw = quaternion_from_yaw(self._angle + math.pi / 2.0)
        transform.transform.rotation.x = qx
        transform.transform.rotation.y = qy
        transform.transform.rotation.z = qz
        transform.transform.rotation.w = qw

        self._broadcaster.sendTransform(transform)
```

Differences from the static version:

- `TransformBroadcaster` (no "Static") publishes on `/tf`.
- It runs **on a timer**, and every message gets a **fresh timestamp**. A stale
  stamp makes listeners complain that the data is too old.
- The rotation actually changes, so we need a real quaternion.

### Quaternions without the headache

ROS stores rotations as quaternions, not as roll/pitch/yaw. For a rotation
about Z only (which is all a ground robot needs):

```python
qz = sin(yaw / 2)
qw = cos(yaw / 2)
qx = qy = 0
```

That is the whole formula for the flat case. For the general case use
`tf_transformations`:

```python
from tf_transformations import quaternion_from_euler, euler_from_quaternion

q = quaternion_from_euler(roll, pitch, yaw)     # -> (x, y, z, w)
roll, pitch, yaw = euler_from_quaternion([q[0], q[1], q[2], q[3]])
```

(Install with `sudo apt install ros-humble-tf-transformations`.)

## Listening: asking TF2 a question

[`tf_listener.py`](../src/ros2_basics_py/ros2_basics_py/tf_listener.py):

```python
from tf2_ros import TransformException
from tf2_ros.buffer import Buffer
from tf2_ros.transform_listener import TransformListener


class TfListener(Node):

    def __init__(self):
        super().__init__('tf_listener')
        ...
        self._buffer = Buffer()
        self._listener = TransformListener(self._buffer, self)
        self._timer = self.create_timer(1.0, self.lookup)

    def lookup(self):
        try:
            transform = self._buffer.lookup_transform(
                self._target, self._source, rclpy.time.Time())
        except TransformException as exc:
            self.get_logger().warn('lookup failed: %s' % exc)
            return

        t = transform.transform.translation
        self.get_logger().info(
            '%s is at x=%.2f y=%.2f z=%.2f in %s'
            % (self._source, t.x, t.y, t.z, self._target))
```

- **`Buffer`** stores the recent history of every transform it hears (10 s by
  default). **`TransformListener`** is what fills it from `/tf` and
  `/tf_static` in the background. You need both, and you must keep references
  to both.
- **`lookup_transform(target, source, time)`** answers *"where is `source`,
  expressed in `target`?"* The argument order surprises everyone; read it as
  "into `target`, from `source`".
- **`rclpy.time.Time()`** — an all-zero timestamp — means *"the latest
  available"*. That is what you want most of the time. Pass a real stamp when
  you need the transform as it was when a specific measurement was taken.
- **Always wrap it in `try/except TransformException`.** A lookup fails for
  perfectly normal reasons: the buffer is still filling at start-up, a
  broadcaster died, the timestamp is outside the buffer window. A lookup that
  is not guarded will crash your node in its first second of life.

The magic is that nobody publishes `odom → laser`. TF2 composes it from
`odom → base_link` (dynamic) and `base_link → laser` (static).

## Try it

Start all three nodes with the launch file:

```bash
ros2 launch ros2_basics_py tf_demo.launch.py
```

The listener prints the composed `odom → laser` position once per second, and
it moves in a circle.

Inspect the tree from outside:

```bash
ros2 topic echo /tf_static --once          # published once, still there
ros2 run tf2_ros tf2_echo odom laser       # the same lookup, from the CLI
ros2 run tf2_tools view_frames             # writes frames.pdf — the tree
```

`view_frames` listens for a few seconds and writes a PDF of the whole tree
with publish rates. When someone says "my TF tree is broken", this is the
first thing to look at.

Visually:

```bash
rviz2
```

Set **Fixed Frame** to `odom` and add a **TF** display. You will see
`base_link` orbiting and `laser` riding along 20 cm in front of it.

**Break it on purpose:** run a second broadcaster that also publishes
`base_link` as a child:

```bash
ros2 run tf2_ros static_transform_publisher \
    --x 1 --y 1 --z 0 --frame-id odom --child-frame-id base_link
```

Now two nodes claim the same child frame. Watch the `TF_REPEATED_DATA`
warnings and the jittering frame in RViz. Then stop it.

## Common mistakes

**`Could not find a connection between 'odom' and 'laser'`**
One link of the chain is missing, or a frame name has a typo. Run
`ros2 run tf2_tools view_frames` and look at the actual tree.

**`Lookup would require extrapolation into the past/future`**
The transform you asked for is outside the buffered window. Use
`rclpy.time.Time()` for "latest", check that broadcasters use
`self.get_clock().now().to_msg()`, and check `use_sim_time` agrees across all
nodes.

**Everything is rotated wrongly, or mirrored.**
You swapped `frame_id` and `child_frame_id`, or swapped the arguments of
`lookup_transform`.

**`TF_NAN_INPUT` or transforms ignored.**
The quaternion is all zeros. Set `w = 1.0` for no rotation.

**`TF_REPEATED_DATA` warnings.**
Two broadcasters publish the same child frame. Each frame gets exactly one
parent and one publisher.

**Static transform published on a timer.**
Works, but wastes bandwidth and defeats the point. Use
`StaticTransformBroadcaster` and publish once.

**A frame name with a leading slash (`/base_link`).**
Not allowed in ROS 2 TF. Use `base_link`.

---

## Recap

- TF2 is a tree of frames; each frame has one parent.
- Fixed relationships → `StaticTransformBroadcaster`, published once on
  `/tf_static`.
- Moving relationships → `TransformBroadcaster`, on a timer, fresh timestamp
  every message, on `/tf`.
- To read: `Buffer` + `TransformListener`, then
  `lookup_transform(target, source, rclpy.time.Time())` inside
  `try/except TransformException`.
- Rotations are quaternions. `(0, 0, 0, 1)` is identity.
- `view_frames`, `tf2_echo` and RViz are your debugging tools.
